# 飞书端操作手册

## 前置条件

```
Multica 中：Spendly-Architect 已连接飞书 Bot
飞书中：Bot 已加入你的项目群
你已通过首次绑定链接完成账号关联
```

> 官方文档：https://multica.ai/docs/zh/lark-bot-integration

## 核心规则（来自官方文档）

| 规则 | 说明 |
|------|------|
| 1 Bot = 1 智能体 | 每个 Bot 只对应一个 Agent |
| 群聊必须 @Bot | 不 @ 的消息不会触发 Agent |
| 私聊不需要 @ | 直接发消息即可 |
| `/issue` 创建 issue | 第一行=标题，其余=描述 |
| 会话按聊天隔离 | 同一聊天中的消息保留在同一会话 |

## 架构：为什么只需要 Architect 的 Bot

```
飞书群
  │
  │ @Spendly-Architect Bot
  ▼
Architect 接收你的消息
  │
  ├── 需要自己做的 → 直接处理（分析、审查、归档）
  │
  ├── 需要 Builder 做的 → 在 Multica 中 @Builder 派发
  │     Builder 完成 → Architect 被唤醒 → 回复到飞书
  │
  └── 需要 QA 做的 → 在 Multica 中 @QA 派发
        QA 完成 → Architect 被唤醒 → 回复到飞书
```

你只和 Architect Bot 对话，Architect 在 Multica 内部协调 Builder 和 QA。

## 日常操作

### 1. 确认 Architect 的拆分方案

**飞书收到 Architect 消息：**
> 已分析设计文档，建议拆分为 8 个 change...是否同意？

**你回复：**
```
同意，按 1→2→3→4→5→6→7→8 顺序执行。
```

### 2. 编译验证

**飞书收到 Architect 消息：**
> Builder 已完成 Change 1 实现，请编译验证。

**编译通过，你回复：**
```
编译通过。
```

**编译失败，你回复：**
```
编译失败，错误：[粘贴错误信息]
```

Architect 会自动 @Builder 修复。

### 3. 催促停摆的 Agent

**飞书收到自动化监控通知：**
> 子 issue qqw-9 停摆超过 20 分钟

**你回复：**
```
请检查 qqw-9 的状态，如有阻塞请报告。
```

Architect 会检查并 @Builder 继续。

### 4. 查看进度

**你发消息：**
```
当前项目进度如何？
```

**或查看具体 issue：**
```
qqw-9 进展如何？
```

### 5. 暂停/恢复

**暂停：**
```
暂停开发，等我通知再继续。
```

**恢复：**
```
继续开发，开始下一个 change。
```

### 6. 用 /issue 创建新需求

```
/issue 调整默认分类列表
把"游戏"改为"教育"，并添加"旅行"分类。
```

第一行自动成为 issue 标题，其余为描述。

## 通知分级

| 级别 | 事件 | 你的响应 |
|------|------|---------|
| 🔴 需要决策 | 请求确认方案、技术选型 | 立即回复 |
| 🟡 需要操作 | 编译验证、停摆提醒 | 尽快回复 |
| 🟢 信息通知 | Change 归档、QA 通过 | 有空看即可 |
| ⚪ 自动流转 | Builder ↔ QA bug-fix 循环 | 不需要操作 |

## 手机日常工作节奏

```
早上：
  看飞书通知 → 了解昨晚进展
  如有 Architect 的确认请求 → 回复

白天（碎片时间）：
  收到通知 → 快速回复
  编译验证 → 评论结果
  停摆提醒 → 催促继续

晚上：
  看飞书通知 → 了解今天进展
  如有拆分方案确认 → 回复
```

## 常见问题

| 问题 | 原因 | 解决 |
|------|------|------|
| @Bot 没反应 | Bot 未加入群 / 账号未绑定 | 检查 Bot 是否在群中，重新绑定 |
| Bot 提示需要绑定 | 首次使用 | 打开绑定链接，登录 Multica |
| Bot 不执行 | Agent 的运行时离线 | 检查 Multica Desktop 是否运行 |
| 回复很慢 | Agent 正在执行长任务 | 等待，可在 Multica 中查看执行日志 |

## 进阶：连接多个 Bot（可选）

如果你需要直接在飞书中和 Builder 或 QA 对话（不经过 Architect），可以为它们也连接飞书 Bot：

```
Multica → 智能体 → Spendly-Builder → 集成 → 绑定到飞书
Multica → 智能体 → Spendly-QA → 集成 → 绑定到飞书
```

然后在飞书群中：
```
@Spendly-Builder Bot 修复 qqw-9 的编译错误
@Spendly-QA Bot 为 Change 3 补充边界测试
```

但通常不需要——Architect 会自动协调。
